## Product requirements

### World and game loop

- 场景是一座月圆之夜的巨大封闭哥特教堂，是真实 Three.js 透视 3D 世界，不是静态背景或按钮式地图。视觉采用有意的低模、低内部渲染分辨率、柔化/像素化、昏暗月光与局部暖光；心理恐怖来自空间异常、血迹、低语和环境变化，不使用跳脸惊吓、频闪或强闪光。
- 玩家从小庇护地出发，通过探索、瞄准射击、净化敌对生物、恢复机器、在线生产、升级和永久点亮房间逐步占领教堂，最终组装月亮炮并由玩家亲自瞄准射击月亮通关。
- 主循环不得保留任何会归零并强制胜负的十二分钟倒计时。等待生产时，玩家仍可探索、瞄准事件、升级或查看地图/契约；风险只存在于主动进入的未知/未净化区域。

### Controls and tutorial

- 键盘移动严格为离散方格：`A` 左转 90°、`D` 右转 90°、`W` 在前方可通行时前进一格。转向和移动有短暂平滑过渡，但逻辑坐标和朝向在每步结束后保持离散、确定；不允许自由走位或自由旋转镜头。
- 鼠标仅作有限瞄准与轻微扭头；左键单击或按住连续发射无限银币。触屏必须提供前进、左转、右转、发射、`B` 和暂停的等价控件。
- “月下低语”引导期间，移动保持锁定。神秘声音先说明银币、机器与第一庇护地，随后要求玩家通过真实 Three.js 瞄准/射线命中完成第一台机器充能，再实际打开 `B` 查看已经获得的能力，最后才解锁 `W/A/D`。不得用自动完成、按钮列表或隐藏调试按钮代替这些步骤。

### Map, rooms, and permanence

- 地图至少有 12 个可到达、具有明确拓扑关系的方格/房间节点，并包含多个可辨识的教堂区域、门、走廊、侧堂、起始庇护地和最终月炮区域。门、阻挡和朝向必须由规则层判断；未探索空间由门与黑暗在 3D 场景中遮挡。
- 至少 4 个不同的安全区/生产节点随推进被净化并永久解锁。每个主要区域至少有可辨识的场景变化以及怪物、机器或资源门槛；地图推进不能表现为外围网页按钮列表。
- 已净化房间不会再次被攻陷。它的永久安全状态、生产者和主线推进跨击倒和存档恢复保留，并在 3D 场景中通过黑暗退去、灯光/材质/环境变化得到可见反馈。

### Shooting, upgrades, creatures, and production

- 银币没有弹药或射击成本。命中机器投入充能；命中怪物累计净化伤害。至少实现齐射、威力、射速三类枪械成长，其中威力/等价伤害升级必须可证明减少同一怪物所需命中次数或提高每次命中的净化伤害。
- 所有玩家可见文案、音画提示和文档使用“银币”，不得残留以“铜币”为资源的旧规则。可升级机器在 3D 场景内清楚显示当前等级、下一等级总需求和仍差点数；`B` 界面只展示已获得能力，并显示全局生产速率。
- 至少有 3 类可辨识的诡异生物。它们具有不同敌对外形或行为提示、不同净化阈值以及不同产物/效率；净化后自动驻留原处，变为可辨识的净化形态并全自动生产，不需要玩家指派。
- 自动生产至少覆盖银币充能、圣水、十字架三类资源/产物。机器可自动吸收产物，或依照界面和文档明确说明的确定性转化规则推进；生产率、累计量、消耗与门槛必须由规则层维护并可测试。
- 只有游戏打开、处于前台、获得焦点且未暂停/未打开 `B` 菜单时，已占领安全区才持续生产。刷新、关闭、失焦、切后台、暂停和 `B` 菜单期间均不生产，也不在恢复时补算离线收益。

### Failure, save, pacing, and endgame

- 被怪物击倒后返回确定性选择的最近已占领庇护点。只扣除本次探索携带所得的少量份额（实现和文档必须固定为 10%–25% 范围内的一种比例）；不得扣除建筑等级、机器升级、已净化怪物、已占领房间、已解锁生产者或主线进度。
- 存档至少保存版本、地图坐标与朝向、资源、生产者、房间状态、升级、主线阶段和累计有效游戏时间。刷新后必须由玩家明确选择继续；损坏或旧版本存档安全拒绝，不能令页面崩溃。
- 正常首次通关目标为约两小时并包含在线生产等待。确定性参考策略在 100–140 分钟有效游戏时间内通关，轨迹必须实际依赖至少三类生产者的产出并跨越资源/占领门槛；不能通过等待离线补算或旧十二分钟计时胜利。
- 最终区域仅在所需资源和教堂占领条件同时满足后开放。月亮炮至少有炮身、圣水冷却、十字架瞄具、银币弹芯四个在 3D 场景中可见的组装阶段。
- 完成月亮炮后，玩家必须实际瞄准并射击才能发动多阶段月亮战。每个阶段产生可辨识的远景月亮/天空变化和音画反馈；最后一击触发明确通关结算，不能由计时器或自动剧情替代。

### Presentation, UI, audio, accessibility

- 游戏始终使用全屏沉浸式布局，不出现网页式外围 `header`、`aside` 或 `footer`。必要提示、`B` 契约、暂停、资源/生产摘要、方位/地图和结算均是可收起的游戏内覆盖层；核心提示、文字和命中反馈不得被低分辨率后处理模糊到不可读。
- 使用程序化音频或仓库内合法素材提供低沉循环环境音，以及具有方向/情境差异的低语、脚步、怪物、机器、银币射击、净化和月亮炮音效。音频仅在用户交互后启用，提供可持久或会话内有效的静音控制，音频失败不得阻止游玩。
- 桌面视口 `1440×900` 和 `1440×1100` 可完成核心流程。宽度 `320`、`375`、`414`、`768` 均不得产生页面级横向/纵向溢出，覆盖层可在内部滚动且触控目标可操作。
- 尊重 `prefers-reduced-motion`：非必要空间动画停用或缩短为不超过 150ms 的透明度反馈；不得用频闪传达信息。键盘焦点环清晰可见，常规游戏控件具备 default、hover、focus-visible、active、disabled，以及在语义适用处的 loading/error/success 状态。WebGL 创建失败或上下文丢失时显示可操作的恢复提示并冻结危险与生产。
- Hallmark 设计约束：沿用“封闭哥特教堂”这一专用游戏结构，不引入营销页式导航/页脚；主题为 atmospheric 的自定义暗色月光体系，主锚点从旧铜色改为银白/月蓝，血色仅作低占比危险反馈。颜色、字体、间距、动效和焦点样式使用命名 token；新增颜色使用 OKLCH；间距遵循 4px 基准；UI 动效只修改 `transform`/`opacity` 并使用命名缓动。顶部 CSS 注释保留 Hallmark 决策与 pre-emit critique 记录。

## Acceptance criteria

- AC1: 从无存档首次进入，玩家能在真实 WebGL 2 的 Three.js 教堂中完成“开始 → 引导 → 探索 → 净化/生产/升级 → 占领 → 组装月亮炮 → 亲自射击月亮 → 通关结算”的可玩闭环；页面不包含旧十二分钟归零胜负循环、网页式外围布局或把地图伪装成按钮列表的实现。
- AC2: 引导通过真实射线命中依次验证瞄准/射击、第一台机器充能和实际打开 `B`，之后才解锁移动；键盘 `A/D/W` 分别执行平滑的离散 90° 转向和一格前进，阻挡有效，鼠标仅有限瞄准/扭头，按住左键可用无限银币连续射击，触屏有全部等价操作。
- AC3: 当前规则和场景实现至少 12 个拓扑相连的可到达节点、多个可辨识教堂区域、门/走廊/侧堂/起始庇护地/最终月炮区和至少 4 个永久安全生产节点；黑暗/门遮挡未探索空间，每个主要区域存在场景变化和怪物、机器或资源目标，净化后有可见且永久的环境变化。
- AC4: 银币命中机器会充能、命中怪物会累积净化伤害；至少齐射、威力、射速三类升级实际改变射击或伤害规则，威力成长能降低等价击杀命中数；场景机器显示当前等级、下级总需求和剩余点数，`B` 只列已有能力和准确的全局生产速率，所有玩家可见内容不再使用“铜币”。
- AC5: 至少三类敌对怪物具有不同的净化阈值、产物/效率和敌对/净化 3D 外观；净化后原地自动驻留并分别支持银币充能、圣水、十字架的在线生产。累计、速率、自动吸收/转化和资源门槛有清楚游戏内说明，且生产无需手动指派。
- AC6: 未净化区域的怪物可击倒玩家；击倒后玩家返回最近已占领庇护点，只损失固定在 10%–25% 的本次探索携带所得，建筑等级、机器升级、怪物净化、安全区、生产者和主线进度完全保留；净化房间永不重新变为敌对。
- AC7: 规则层在低帧率、大步长和细粒度步进下给出等价结果；确定性参考策略在 100–140 分钟有效游戏时间内依靠三类在线生产资源完成全部门槛并通关。暂停、`B`、失焦、后台、关闭和重开期间不会推进危险或生产，也没有离线补算。
- AC8: 最终区同时受资源和占领条件门控；炮身、圣水冷却、十字架瞄具、银币弹芯四个 3D 组装阶段逐步可见。组装完成后只有玩家实际瞄准/射击才能推进至少两个可辨识的攻击阶段，月亮远景随阶段变化，最终射击产生音画反馈并进入明确胜利结算。
- AC9: 版本化存档可安全保存/恢复地图坐标、朝向、资源、生产者、房间、升级、主线和有效游戏时间；刷新后明确显示继续选择，恢复不补离线收益。暂停、`B`、失焦、后台和 WebGL 上下文丢失都冻结生产与危险，损坏/旧存档和 WebGL 失败均有不崩溃的恢复路径。
- AC10: 游戏具有符合低模、低分辨率、柔化暗色像素风的封闭哥特 3D 空间和非跳脸心理恐怖反馈；环境、低语/脚步/怪物/机器/射击/净化/月炮音频在首次用户手势后启用并可静音。桌面 `1440×900`、`1440×1100` 与宽度 `320/375/414/768` 均无页面溢出、文字和命中提示可读、触控可完成核心操作、焦点清晰，并正确处理 reduced-motion 与无 WebGL。
- AC11: 规则和场景保持解耦且不需要后端或联网运行时依赖；`pnpm test`、`pnpm build`、`pnpm test:e2e` 全部通过。单元测试覆盖移动/阻挡、净化/回撤、自动生产、永久安全区、升级、存档、阶段解锁、约两小时策略和月亮战；Playwright 覆盖真实 WebGL、鼠标命中、引导、`A/D/W`、`B`、净化、生产增长、保存恢复、月炮组装/实际通关、小屏触控/布局和零页面错误；README 与设计文档准确说明操作、地图、生产、失败、时长和终局，Vite/GitHub Pages `/Coin/` 子路径构建兼容。

## Constraints

- 保持 React、TypeScript、Three.js、Vite、pnpm 技术栈；不得引入后端、账号系统或必须联网的运行时依赖。
- 规则层不得依赖 Three.js、React、DOM 或真实墙钟；视觉层消费规则状态，不能自行决定资源、伤害、移动、生产、门槛或胜负。
- 数值推进对低帧率和合法大步长确定，单次异常大步长有安全上限；不把浏览器后台时间当作在线游戏时间。
- 自动化可通过版本化存档、测试构造器或仅供测试的加速接口缩短浏览器流程，但不能增加玩家可见的调试按钮、绕过生产/门槛规则或替代规则层两小时模拟。
- 所有新资产必须是程序生成或仓库内具有合法使用权的素材；不得把远程 CDN/字体/音频/模型作为运行必需项。
- 保留用户已有的无关改动，不重写或清理 Git 历史；不得使用 force push。

## Non-goals

- 多人、账号、云/服务器存档、支付、排行榜、成就平台或离线收益。
- 写实高模资产、完整物理引擎、自由走位、自由镜头、VR、手柄支持或无限关卡。
- 跳脸惊吓、强闪光、频闪、血腥写实特写，或改变为纯动作射击游戏。
- 用按钮列表、静态插画、预录视频、自动剧情或隐藏调试控件代替真实 Three.js 探索、射线命中、生产门槛和最终射击。
- 与本任务无关的依赖升级、目录清理、历史改写或功能扩张。

## Verification plan

### Required automated commands

1. `pnpm test`
   - 必须从仓库根目录运行并通过。
   - 检查移动/阻挡、净化/击倒回撤、三类生产、永久安全区、升级伤害、存档/无离线收益、阶段解锁、粗细步进等价、100–140 分钟策略和多阶段月亮战。
2. `pnpm build`
   - 必须从仓库根目录运行并通过 TypeScript 与 Vite 生产构建。
   - 另在 Windows PowerShell 运行 `$env:PAGES_BASE_PATH='/Coin/'; pnpm build; Remove-Item Env:PAGES_BASE_PATH`，并检查产物引用以证明子路径部署兼容。
3. `pnpm test:e2e`
   - 必须在新构建对应的当前代码上运行并通过，不复用陈旧截图作为结论。
   - Playwright 产物先写入当前 iteration scratch；最终 evidence 阶段仅提升准入的 criterion-level 证明。

项目没有独立 lint script；lint 不作为独立 gate，TypeScript 类型检查由 `pnpm build` 执行。若实现新增 lint script，则它也必须通过，但不能替代三条必需命令。

### Required browser checks

- `1440×900` 与 `1440×1100`：真实 WebGL 2 场景加载、无外围网页布局、教程真实命中、`A/D/W` 格点移动、`B`/暂停冻结、至少一次净化与生产增长、保存继续、后期四段月炮和实际射击通关、零未处理 page error/console error。
- 宽度 `320/375/414/768`：页面无横向或纵向溢出；覆盖层仅内部滚动；触控可完成前进、左右转、发射、`B` 和暂停；文字、准星、命中提示与触控目标可读可用。
- reduced-motion：非必要移动/异常效果被停用或降级且游戏仍可操作；键盘焦点可见。
- WebGL 创建失败/上下文丢失：显示恢复提示，生产和危险被冻结，不发生 React 崩溃。
- 音频：首次手势前不自动播放；手势后环境/事件音可启动；静音立即生效且不影响游戏逻辑。

### Evidence expectations

- 每个 AC 的证据必须引用本轮新运行的命令输出、精确测试名称或当前截图/状态 trace；“代码看起来正确”不足以单独 PASS 动态行为。
- 两小时节奏证据必须包含确定性模拟的完成有效时间、关键资源/占领/炮体里程碑和三类生产累计，不能真实等待两小时。
- 最终月亮战证据必须证明玩家输入导致阶段递增与胜利，而非仅展示已胜利存档。
- 响应式截图和 DOM 尺寸断言均需覆盖四个指定宽度；视觉检查需确认文字/命中可读且没有跳脸/频闪设计。
